# 任务台

Hana v2 应用，版本 0.11.4。把 Super Productivity 接入对话，SP 是唯一任务记录源。
JavaScript ES modules，无构建步骤；sdk/ 为随应用分发的 Hana SDK。

## 首次安装：让 Hana 助手引导

安装任务台后，在 Hana 新对话中说：

> 请使用任务台安装引导，检查我的环境并帮助完成 SP 扩展安装与连接；涉及系统授权时先征求我的同意。

0.9.2 随应用提供 `skills/sp-tasks-setup/SKILL.md`。Hana 在新会话或技能刷新时发现该技能；已经打开的会话不会仅因升级就立即获得它。设置页以助手引导为主，旧下载、权限说明和配对入口折叠在「手动安装与连接（备用）」中。

这是安装指导，不是新安装器，也不新增工具权限。助手必须先确认当前会话真正拥有的文件、终端、受控界面和提权能力；能安全完成的步骤才代办，其余只请用户完成必要的一步。Windows native 身份依赖不会因为添加技能而消失，系统初始化仍需明确同意和宿主支持的管理员授权。SP 插件通过受支持的安装界面安装，不直接覆盖程序、数据库或安装目录。配对码不进入聊天或工具结果。

发布源是 GitHub 仓库 [shenmingganlin/hana-sp-tasks](https://github.com/shenmingganlin/hana-sp-tasks)。每个版本以固定 tag（如 `v0.10.2`）的 Release 提供任务台安装包、Hana 市场条目和单独的 SP 扩展 ZIP，Release 说明列出版本对应关系和 SHA256。不跟随未固定版本的 `latest`，不执行远程安装脚本。任务台内置的 SP 扩展包继续保留作为兜底。发布包与校验值须来自同一已确认来源；同源哈希用于发现文件损坏，不等于独立的作者身份或供应链认证。

完成标准是重新读取到基础 REST 正常、桥接运行、SP 已连接且版本兼容，不是“下载完成”“插件已启用”或“安装命令退出成功”。本轮不代用户初始化系统、安装 SP 插件或创建真实测试任务。

## 连接与权限

- SP 桌面版需开启本地 REST API，默认 http://127.0.0.1:3876。
- 自动读取 Windows SP 数据目录里的 REST 令牌，也可手填。设置页可切回自动读取，不会把令牌回传页面。
- 原有 REST 工具使用工具暴露、资源读取、回答前钩子；出站白名单仍只允许本机。
- 0.6.0 增加基于 SP 官方插件 API 的可选桥接（本项目开发，并非 SP 官方出品）。Windows 的 Hana 托管服务需要 `app/runtime.execute`、`app/runtime.native`、`app/runtime.network`，并使用 `profile:native` / `network:external`；这是较宽的宿主授权，安装时应明确审阅，不能宣称仍是旧版权限。实际服务代码只监听 `127.0.0.1:3877`，不对外发送请求，不启动任意脚本。
- 桥接默认停用。仅用户在设置页点击配对后才启用，卸载/停用由宿主回收服务。独立管理令牌与 SP 插件令牌分离，不读取或传送 Hana 主令牌。
- 0.7.0 将 SP 扩展安装包和安装指引并入任务台设置。Hana 侧只有一个任务台应用；SP 仍需通过自己的插件界面加载扩展。新增 `app/ui.clipboard-write` 仅用于用户点击复制配对码，不读取剪贴板；拒绝该权限仍可手动复制。
- 0.11.3 起，设置页保存扩展包不再经过卡片：按钮先打开系统文件夹选择框，再由应用后台把校验过的内置 ZIP 写进选中的文件夹。Hana 只允许卡片或预览面调用 `resources.saveFile`，设置面没有写文件的对话框；`resource.pick` 可以在设置面选目录。`app/resources.write` 仍是应用级写入授权，安装升级时应审阅；当前实现只写一个固定文件名的 ZIP，不自动安装、不修改 SP 数据。拒绝此权限不影响基础 SP 操作。
- 0.11.4 新增 `app/ui.open-external`，只用于设置页推荐卡的「下载 SP 桌面卡片」按钮：用户点击时打开固定的 GitHub Release 页面；宿主没有确认打开或权限被拒时，退回复制下载链接。不读取其他页面，也不在后台发起网络请求。
- 已按本机 SP 19.3.1 源码核对。REST 令牌没有细分写权限；SP 的 MCP 助手权限是另一条更窄的通道，不能通过开启 MCP scopes 扩大 REST。

## 对话工具

- sp_tasks_overview：今天、逾期、收件箱、当前计时，可包含已完成任务。
- sp_tasks_search：按标题、项目、标签搜索，支持归档区和分页。
- sp_tasks_get：完整备注、父子关系、按日工时和重复规则 ID。
- sp_tasks_create / sp_tasks_update：新建与批量修改，项目/标签可按完整唯一名称或 ID 指定。
- sp_tasks_manage：归档、恢复、永久删除任务，以及只读查看恢复进度、继续未完成的恢复；父任务操作可能影响子任务。
- sp_tasks_timer / sp_tasks_log_time：开始/停止计时，补记或覆盖指定日工时。
- sp_tasks_context：列出现有项目和标签。
- sp_tasks_repeat：查询、创建、修改、暂停和删除已有任务的重复规则。
- sp_tasks_notes：独立笔记的查询、新建、修改、移动和删除。
- sp_tasks_counters：读取已有习惯/计数器，设置历史日数值或累加今天。
- sp_tasks_bridge：只读检查配套插件是否启用、运行和连接；不返回配对凭据。
- sp_tasks_projects：配对后查询、新建、改名和修改项目颜色/图标/积压区/菜单显示；显式授权后永久级联删除项目。
- sp_tasks_tags：配对后查询、新建、改名和修改标签颜色/图标；不提供删除标签。
- sp_tasks_counter_config：扩展 0.3.0 起，配置已有计数器的名称、图标、启用与按钮显示；明确确认名称和历史数据范围后删除停止中的计数器。
- sp_tasks_counter_control：扩展 0.4.0 起，查询和显式启动/停止已有秒表，查询和暂停重复倒计时提醒；开关仅作用于本机。
- sp_tasks_workspace：扩展 0.3.0 起，读取和重排项目普通列表或父任务的子任务列表，读取或打开任务详情，以及受限更换叶任务父项。排序必须保留完整任务集合并核对原顺序；不移动积压任务或启动计时。
- sp_tasks_work_context：扩展 0.4.0 起，读取和切换活动项目、标签、今天和收件箱；切换清除任务详情选择，不启动或停止计时，也不导航路由页面。
- sp_tasks_preferences：读取和修改十个白名单分区。0.3.0 起支持声音、专注背景音、上下班与午休时段；0.4.0 起支持番茄钟参数、专注默认行为和休息提醒；0.5.0 起支持显示、任务行为、计时默认值与提醒、排期提醒默认值。必须提供刚读取的原值，写后读回核对。
- sp_tasks_ui：扩展 0.5.0 起，提交八个固定面板命令，包括专注覆盖层、添加任务栏、笔记和问题侧栏。只能确认提交，不能确认画面或控制专注会话。
- sp_tasks_attachments：扩展 0.5.0 起，查看、添加和移除活动任务的 HTTP/HTTPS 链接附件。完整附件指纹防止覆盖新改动，保留已有文件、图片和隐藏元数据；不传输或打开文件。
- sp_tasks_keyboard：扩展 0.5.0 起，读取和设置内置应用与任务快捷键。校验完整配置版本和新冲突，保留系统热键及插件配置；不模拟按键。
- sp_tasks_capabilities：只读查看当前应用/扩展版本、兼容性和完整能力清单，不返回配对凭据。

总计 24 个工具；原有 REST 工具入口不依赖插件。历史完成时间回写需要 0.2.0，计数器配置、任务结构和原有偏好需要 0.3.0，秒表与工作上下文控制需要 0.4.0，本轮新增操作需要 0.5.0。项目和标签读取可继续使用原有 sp_tasks_context。

## 0.11.0 桌面卡片皮肤跟随

设置页新增「桌面卡片」。打开「跟随 Hana 的主题」后，任务台把 Hana 当前主题的 id 原样写进 `%APPDATA%\SP 桌面卡片\theme.json`；桌面卡片 0.4.0 起 11 套 Hana 主题都做成了皮肤，Hana 用哪套，卡片就用哪套。`auto` 用暖纸，认不出的主题退回新暖纸。每 5 秒看一眼 Hana 的设置，换主题时卡片跟着换；关掉开关会删掉这个文件。没装桌面卡片时不会创建目录，设置页会说明。

桌面卡片 0.4.0 起支持这个通用外部主题文件。任务台只写这一个文件，不改卡片的设置，也不依赖 SP 扩展或桥接。

## 0.10.2 恢复父任务预估

SP 只在子任务的完成状态或预估变化、以及增删移动子任务时重算父任务预估，取值为未完成子任务「预估减已用」之和；补记工时和 SP 自己的恢复都不触发重算。任务台恢复时把子任务改回归档前的未完成状态，会触发这次重算，使父任务预估变成子任务剩余预估之和（子任务继承了父任务预估时，正好是「原预估减已投入」）。0.10.1 说明中「在 SP 界面恢复也一样」不成立，已删除。

现在 archive 为有子任务的父任务记下归档前预估。restore 和 repair 先修完所有子任务，再检查父任务：只有当前预估正好等于 SP 重算出的值时才写回原值并读回核对（`completionSync.estimatesRestored` 计数）；用户在恢复后自己改过的预估不覆盖。子任务修复未完成时，父任务记为 `SP_ESTIMATE_PENDING`，等 repair 修完子任务后再写回。之后在 SP 中勾选或修改任一子任务，SP 仍会按自己的规则重算。0.10.2 之前的恢复记录没有预估信息，照旧不处理。

## 0.10.1 归档保真与报错修正

SP 的原生归档会清空计划日 `dueDay`、计划时间 `dueWithTime` 和提醒，截止日不受影响。archive 现在把计划日和计划时间与完成信息一起记入恢复记录，restore 和 repair 在任务仍未安排时写回并读回核对；恢复后用户已经重新安排的不会被覆盖。提醒无法经 REST 还原。旧版本留下的恢复记录没有计划信息，照旧只恢复完成信息。

项目和标签的 color 也接受 `rgb(r, g, b)`，会转成 `#rrggbb` 写入，SP 读出的默认颜色可原样写回。删除已归档任务时返回 `SP_TASK_ARCHIVED`，提示先恢复再删除；SP 接口本身对这种情况只报 `TASK_NOT_FOUND`。

## 0.10.0 桥接、下载与设置页精简

设置页顶部两行分别显示本地接口和 SP 扩展是否连通，检测细节、安装步骤和排障说明按状态折叠。ZIP 结构、CRC 与内部清单在 `scripts/bundle-companion.mjs` 构建时校验；运行时下载路由只核对大小和 SHA256，设置页只读 `package.json`。运行失败后保留不含凭据的诊断，刷新状态不自动启动服务。

桥接在首次验证后复用同一托管进程，一条命令只发一次请求；请求失败才重新检查宿主。读命令在进程丢失时重试一次，写命令不重发。仍在启动的进程（Windows 冷启动约一分钟）保留给下次调用接管，超过 180 秒才停止。SP 扩展 0.6.0 改为长轮询：桥接挂住空轮询直到有命令或 20 秒到期，命令无需等待下一轮。0.5.0 仍完全兼容，只是每条命令多约 0.4 秒延迟；设置页会提示可更新。

## 0.9.1 下载修复

Hana 设置 iframe 没有 `allow-downloads`，Blob 链接的 click 不抛错但下载被拦截。0.9.0 的「已发起下载」因此不能证明任何文件操作。旧测试在顶层浏览器页面运行，未覆盖真实 sandbox，这是已修复的测试缺口。

官方 `resources.saveFile` 只允许 card/preview，不能直接放在 settings。0.9.1 到 0.11.2 用一张普通卡片承载保存；0.11.3 改成设置页选文件夹、应用后台写入，卡片已从清单移除。旧的卡片保存流程只读取和校验内置 ZIP，不启动桥接、不修改 SP、不保存文件；新的后台写入同样只写 `hana-sp-bridge.zip`。

SP 扩展保持 0.6.0，24 个工具和原 SP 权限不变。

## 0.9.0 能力补齐

新增三个工具和四个偏好分区，未增加 Hana 或 SP 权限。SP 扩展随任务台更新到 0.5.0，Hana 仍只安装一个任务台应用。

- 链接附件：先 list，再将 revision 作为 expectedRevision 添加或移除。SHA256 覆盖所有附件及其隐藏字段；写前重读，写后核对整个数组。只编辑具有唯一 ID 的 HTTP/HTTPS 链接；其他附件计入 otherCount 并原样保留。URL 会规范化，相同 URL 不重复添加；不访问链接或删除本地文件。
- 面板命令：focus.show/hide、addTask.show/hide、notes.toggle、issues.toggle、sidePanel.hide、pluginPanel.hide。返回 verification:submitted，不能说成已确认画面显示。focus.hide 会取消尚未开始的准备倒计时；切换笔记/问题面板会隐藏其他非任务面板。重复 toggle 会反转，因此结果未知不能盲重试。
- 应用内快捷键：get 返回内置键名及完整配置 revision。update 只接受这些键名，null 解绑；规范按键大小写、检查新冲突，保留旧有冲突。系统热键、插件和未知配置不能修改，但全部参与指纹校验并保留在完整写入中，避免 SP 的重新注册 effect 丢失系统热键。配置读回不等于操作系统热键注册成功。allowConflicts:true 仅用于用户明确接受的冲突，不自动改动其他键。新增 showHelp:? 还必须明确接受布局相关冲突风险，成功会返回 help-layout-dependent 警告；已有 ? 保留。静态检查不保证所有布局都无冲突，动态插件键名仅显示 external-binding。
- display：动画、竖向操作栏、庆祝效果、启动提示、桌面徽标和托盘倒计时。
- taskBehavior：删除确认、计时自动加入今天、子任务完成后自动完成父任务、托盘任务显示和笔记格式。自动加入今天可影响正在计时的未排期任务；父任务自动完成影响后续完成事件。SP 删除确认开关不替代工具的删除授权。
- timeTracking：新任务/子任务默认估时、超时通知、完成后自动计时下一项和未计时提醒。默认估时不重写已有任务；自动下一项可能在当前任务完成后开始另一个任务。
- reminderDefaults：未来排期的默认提醒选项、提前倒计时横幅、提前时长和窗口前置。不重写已有任务或重复规则的提醒时间，显式 REST 排期也不保证采用 UI 默认选项。提前时长 0 不关闭到点提醒。

新偏好遵循完整 expected 比较及读回核验。单位为毫秒；defaultEstimate 为 0 表示不添加默认估时，trackingReminderMinTime 为 0 仍可在下一次符合条件的正计时 tick 提醒，不表示禁用。字段缺失或类型不符会拒绝，不猜测上游默认值。

本轮还提供独立的上游源码补丁 `../sp-hana-bridge/upstream-patches/0001-persist-plugin-counter-creation.patch`，修复 SP 新计数器创建分支没有完整持久化记录的问题，附基于实际 19.3.1 源码的内存重放测试。补丁尚未应用到 SP，也不包含在可执行扩展中；任务台仍不开放新建计数器，直到修复后的实际 SP 版本通过验证。

界面命令只有 submitted 确认，其他新写入的 applied-state 只表示读回当前状态一致。SP 没有原子比较写接口，不能保证写入与用户编辑或同步隔离，也不以读回成功冒充落盘/跨端同步完成。

## 0.8.0 能力补齐

本版补齐已确认可以通过公开 API 实现的五类能力，未增加 Hana 或 SP 权限。

- 秒表控制：先 status，再以返回的完整 counter 作为 expected 执行 start/stop。已经达到目标状态不会再 toggle；禁用的秒表不会被暗中启用。开关是本机态，累计时长仍由 SP 定期和停止时持久化。重复倒计时提醒可查看/暂停；其启动还需要 SP 界面初始化倒计时，仅调用公开 toggle 不足以保证运行，因此不提供启动或恢复。
- 工作上下文：先 get，再带当前 id/type 作为 expected 切换。支持活动项目、标签、TODAY 和 INBOX_PROJECT，拒绝归档或不存在的目标。切换会清除详情选中项并按现有配置刷新关联服务；不导航路由页面，不停止任务计时，也不启动番茄钟。
- 番茄钟参数：pomodoro 分区支持工作、短休息、长休息时长和长休息前周期数。时长单位为毫秒，0 按 SP 原有语义保留，周期数必须为正整数。不重置正在运行的会话计时和周期计数。
- 专注默认行为：focusDefaults 提供播放时自动专注、准备页、休息暂停任务计时、手动开始休息四项。它只映射实际 focusMode 的行为字段，原 focusMode 背景音合同保留。配置可影响后续播放和当前会话的下一次转换。
- 休息提醒：takeABreak 提供提醒开关、工作阈值、稍后提醒时长、锁屏、全屏休息遮罩及窗口前置。开启提醒或降低阈值可在当前任务计时期间触发已配置的行为；关闭开关不保证撤销已排队的锁屏或遮罩，不会重置已工作时长。

零时长不是统一的关闭语义：短/长番茄休息设为 0 都回退为 5 分钟；工作时长 0 不回退，新会话可在下一次 tick 完成（手动休息超时模式除外）；全屏休息遮罩 0 回退为 5 秒。稍后提醒和遮罩时长均不得超过 2147483647 毫秒，避免 SP 使用的 JavaScript 定时器溢出。

这些操作均在发送前校验参数、连接和版本；写后核对状态，不自动重试结果不明的请求。applied-state 表示已确认 SP 当前状态，不能证明已落盘或完成跨设备同步。expected 比较不是跨进程原子事务，仍应避免并发修改同一对象。

能力清单和设置页从本版开始区分 not_implemented（任务台尚未接入）、unsupported/public_api（当前 SP 公开接口缺口）、unsupported/upstream_bug（已确认上游缺陷），以及已实现但尚未配对/需要升级的能力。后续 0.9.0 补齐常用显示和快捷键偏好、面板命令与链接附件，并核实真正看板与列管理缺少公开入口。

## 0.7.0 整体更新

修复 0.6.1 实机验收中的子任务恢复误报：REST 平面列表中的真实实体才代表活动区/归档区成员，不再将父任务残留的嵌套 `subTasks` 快照当作实体。单独恢复子任务后，再恢复父任务不会重新消费已完成的子项，也不会因旧快照制造 pending 或冲突。真实双区残留和用户修改引发的冲突仍会保留，旧 pending 可用 repair 继续核对。

计数器配置只作用于已有计数器，不改变类型或历史数值，也不直接设置 `isOn`。禁用运行中的秒表会暂停计数，重新启用可能继续。删除需要当前完整名称和 `allowHistoryDelete:true`，运行中的计数器不能删。没有开放新建：SP 19.3.1 的公开 `setCounter` 创建分支没有写入完整的持久化操作记录；仅当下读回成功不能保证重启重放或同步后仍存在。

排序先 get_order，再把完整原顺序作为 `expectedTaskIds`、同一集合的新顺序作为 `taskIds` 提交。最多 200 项，顺序已变、成员缺失或跨积压区会拒绝；成功后读回确认。该比较不是 SP 原子事务，操作期间仍应避免并发编辑。选中任务只打开详情，不接管计时。

更换父项使用公开 `batchUpdateForProject` 的固定窄操作，只接受同一活动项目内的叶任务与顶层父任务，相关任务不能有重复规则，项目积压区必须为空，已有关系必须一致，新父与子任务的完成状态必须相同。被移动任务、原新父及其全部后代的工时和预估必须为零，避免上游不重算汇总的问题。传当前 `expectedParentId` 与目标 `parentId`，后者为 null 表示提升为顶层任务。SP 批量操作会运行全局关系修复，所以预检拒绝可能引发非目标修改的数据；事后核对任务集合、关系、标签、完成元数据和相关工时，不能视为任意任务都可换父项。

偏好设置只使用官方白名单配置 action，内部固定构造正确的持久化 metadata；模型不能传入任意 action、meta 或配置分区。修改前比较完整白名单原值，更新后读回。排除同步、凭据、备份、系统控制、一天起始时间与番茄钟运行状态，避免更改任务日期或泄露设置中的敏感内容。

## 0.6.1 接入与归档修复

三个工具注册路径统一分离宿主注入的 `context` 与业务参数，全部 15 个工具保留未知业务参数拒绝；不修改 Hana SDK 或宿主契约。

归档前先持久保存整棵任务树的 `isDone`、`doneOn`、`wontDoOn` 和父子关系。存储失败时不执行归档。记录按 SP 连接地址和令牌的哈希隔离，不保存令牌明文；未完成的恢复记录不会按 30 天期限删除。它们是恢复操作所需的元数据，不包含任务标题、备注或任务内容副本。

默认恢复会保留完成状态、历史完成时间和“不做”分类。SP REST 本身无法回写历史时间，所以恢复已完成根任务需连接配套插件 0.2.0；插件只通过官方 API 修改 `isDone` / `doneOn`，不改 `wontDoOn`。所有修复都读回验证，成功项逐项消费；单独恢复过的子任务不会在恢复父任务时被再次改写。

恢复中断、响应丢失或部分回写失败时，`failed`、`partial`、`outcomeUnknown` 会反映实际情况。先用 `sp_tasks_manage action:recovery` 查看，再用 `action:repair` 继续待修项；repair 不重发 restore。检测到任务已被用户或同步改动时保留当前值并报冲突。用户明确选择保留现状时，`repair keepCurrentCompletion:true` 仅结束待修项，不修改 SP。存储按连接隔离，换地址或轮换令牌不会自动套用旧连接记录。

0.5.0 热修的布尔快照缺少时间信息和连接身份，不能无声升级成完整记录。无快照或旧快照恢复默认在写入前停止。用户接受 SP 原生恢复会改变完成信息时，可显式使用 `restore allowCompletionLoss:true`：整次根任务恢复不回写完成元数据，返回 `partial` 与 `degradedRoots`；已有完整记录中尚未匹配的项仍保留，以便以后选择 repair 或保留当前值。

公开 SP API 没有关闭完成事件副作用或原子比较后写入的能力。默认保全模式会提前拒绝可能触发下一期任务的完成式重复规则、关联外部 issue 的完成回写，以及父任务缺失或未完成时单独恢复已完成子任务的场景；不会擅自暂停规则或完成父任务。允许原生降级仍需明确接受完成信息变化。普通完成回写仍会触发 SP 的完成事件，其他已安装插件的完成钩子可能执行；三字段保全不代表完全无副作用。操作期间应避免同时编辑相同任务；预检与写入之间仍可能发生手动编辑或同步，读回校验不能宣称跨系统事务。归档子任务必须明确选中其父任务，避免 SP 在标签视图中仅移除标签却报告归档成功。

## 内置 SP 扩展安装

1. 通过 Hana 正常安装流程升级本应用，审阅既有的三项运行权限以及 0.9.1 新增的应用级 `app/resources.write` 资源写入权限。不要直接覆盖安装目录；reload 只重启已安装副本，不会把本仓库源码复制过去。
2. 如需保存扩展包，先在安装授权或 Hana 应用权限页允许 `app/resources.write`，再打开任务台设置，在「SP 扩展」里点「选择位置保存扩展包」，选一个文件夹；保存后可点「复制路径」直接粘到 SP 的文件选择框。点击保存不会自动授予权限。然后通过 SP 设置的插件界面上传 0.6.0 ZIP 并启用；已安装 0.5.0 可继续使用，更新后命令响应更快。无需另找仓库或安装第二个 Hana 应用；不修改 SP 程序、数据库或 asar。
3. 在任务台设置点击「启用并显示配对码」，将配对码只粘贴到 SP 配套插件的「配对 Hana」窗口，随后点击检查插件连接。默认端口 3877 被占用时会报错，不会结束其他程序。
4. 在 Hana 对话先查询 `sp_tasks_capabilities`、`sp_tasks_bridge`、项目/标签/计数器配置列表，再用专用测试对象验收写入。旧插件仍可使用其已有能力，新功能会在写入前要求升级。

Windows 还有一项宿主前提：Hana 的 native sandbox identity 必须先初始化，批准应用权限本身不等于身份已经就绪。按 Hana 随附 APPS.md 的说明，需要管理员为当前使用者及其 Hana 数据目录执行随 Hana 安装的 `hana-win-sandbox.exe --initialize-native-identity --native-identity-home <数据目录>`。设置页如未核验实际系统状态会明确显示未检查，不用 SDK 接口存在冒充身份 ready；本应用不自动初始化系统身份或修改系统权限。

配对码是管理凭据，不要发进对话或公开截图。SP 端使用本机 secret 存储，不放入同步数据；Hana 端凭据只保存在应用自己的数据目录/存储中。断开桥接不会修改 SP 任务。请求超时后未领取的命令失效；已领取的写操作结果不明会标记 outcomeUnknown，不自动重新执行。

回答前的待办摘要有 60 秒缓存，总预算 800ms；配置修改、写入尝试和换日会使缓存失效。
连接失败时不阻塞对话。写请求响应丢失会明确标记结果不确定，不自动重试创建或累加工时。

## 0.5.0 日期语义更正

SP 19.3.1 的 dueDay / dueWithTime 是计划执行日期与时刻，真正截止字段是
deadlineDay / deadlineWithTime。旧版误称前者为截止日，现已更正工具描述并开放真正截止字段。
这次升级不会迁移或修改已有任务日期。

planToday / planForToday 现在写入实际 Today 视图使用的计划日，不再写无效的旧 plannedAt 字段。
清除计划日会同时清除旧计划时刻。SP 可能把今天截止且没有未来计划的任务自动安排到今天。
任务台按本机时区、04:00 的逻辑日换算；如果 SP 修改了一天开始时间，需同步调整 lib/date.js。

## 当前接口边界

REST 不提供项目和标签管理、全局设置、看板管理。可选插件补项目创建/修改/删除、标签创建/修改及受限配置，不是扩大 REST 权限。
公开插件 API 没有 deleteTag，项目完整归档/恢复、番茄钟会话控制、真正看板与列管理也缺少公开写入口；界面状态读取未公开，面板动作只能确认提交。计数器创建分支有持久重放缺陷，独立补丁尚未部署。本版不开放任意 action dispatch。
任务台仍有工程缺口：文件/图片附件传输、更多列表排序、其余偏好及与日期换算联动的日界线。这些不归因于权限，也不能以本轮链接附件和显示设置的支持冒充已完成。
项目删除可能级联活跃/归档任务、笔记和重复规则。归档读取无法严格证明完整，删除始终要求精确 confirmTitle 和 allowCascade:true；不因为当前可见为空就认定安全。
重复规则接口不支持全部模板和提醒设置；不能创建计数器或改变计数器类型。排序仅提供项目普通列表和父任务子列表，不支持标签列表或积压区移动。
