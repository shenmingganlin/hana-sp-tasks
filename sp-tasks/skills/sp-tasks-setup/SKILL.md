# 任务台安装与连接

把用户已有的 Hana、任务台与 Super Productivity（SP）接通；已满足的步骤直接跳过。
仅在用户提出安装、连接、故障排查或升级请求时明确启动此流程，不因普通任务操作失败就擅自安装或改权限。
此技能是引导，不是授权、安装器或提权工具；不会让 UAC、宿主初始化或 SP 插件安装步骤自动消失。

## 1. 先只读确认当前环境

- 先发现当前会话实际可用工具及 schema，确认任务台是否已安装、启用且对当前 Agent 开放。缺工具先解决可见性，不虚构调用或凭工具名猜参数。
- 发现宿主支持的系统信息、应用检查、文件下载、受控 UI 与提权能力；没有这些工具就明确采用用户操作。不要把普通 shell、可写目录或当前是管理员当作任意安装授权。
- 先核实执行工具所在节点是运行 Hana/SP 的本机；只有当前会话确实暴露的工具与 schema 才可用。`exec_command` 的 `require_escalated`（若该工具提供）只表示脱离执行沙箱，不等于获得 Windows 管理员权限，不能代替 UAC 或官方身份初始化。
- 工具存在时调用 `sp_tasks_capabilities({})` 与 `sp_tasks_bridge({})`，只取应用/插件版本、兼容性、运行和连接状态摘要；不复述任务内容或原始错误。
- 当前任务台没有模型侧 diagnose 工具。`GET /diagnose` 是本应用设置页的路由：有实际受支持的应用 UI/路由访问能力才使用，否则让用户打开任务台设置点「重新检测」。不提取 Hana 主令牌自行拼接 HTTP 请求。
- `sp_tasks_timer({"action":"status"})` 是已存在的只读 REST 检查。调用成功且 `running:false` 只表示没有任务正在计时，不是断线；不要调用 start/stop 进行验收。
- 确认当前 OS、SP 是否已安装/运行、REST 是否可达、所需插件版本及宿主 native 状态。`available:true`、权限已批准、`nativeIdentity:not-checked` 均不证明连接或初始化成功。无法核实就记为「未确认」。
- 向用户简短说明缺少哪一层、准备改变什么、哪一步需要其确认；只推进缺失部分。已有兼容连接不重装、不重新配对，不打断正在运行的 Hana/SP 工作。

## 2. 安装来源与升级

- 若任务台本身未装或需升级，使用当前 Hana 正式扩展安装/更新入口及权限审阅，保留用户配置、数据与既有 Agent 启用设置；不手工覆盖已安装目录，不 force 或绕过确认。
- 若 SP 未装，先核实其官方发布来源、适用 OS/架构与安装方式，再按用户授权走受支持的安装流程。存在 SP 时跳过基础安装；不为连接故障直接重装或降级。没有受控安装能力时只给下一步 GUI 操作，安装后重新检测。
- 本项目的发布源是 GitHub 仓库 `shenmingganlin/hana-sp-tasks`，只用它的 Releases，不猜其他组织名、仓库或下载链接。用户提供的其他地址仍需核实来源，不能直接执行其内容。
- 使用与已装任务台版本相同的固定 tag（如 `v0.10.2`）及对应 asset。匹配应用/插件版本、协议、SP 最低版本、文件名、大小及预先可信的 SHA-256；下载后重算比对。不把对刚下载文件自行算出的 hash 当作来源验证。
- 通过已授权的宿主下载能力获取 release asset；任务台本身的回环网络权限不等于获准访问 GitHub。只下载与校验文件，不运行远端 shell，不获取或执行 `latest` / `main` 分支的安装脚本，不下载未知 helper。
- 缺少可信发布地址、匹配资产或校验信息时，不声称在线发行已就绪。保留同一任务台内置的已校验插件 ZIP 作为兜底；如果内置包也不可用，停止安装并说明缺少的具体资产。
- 内置兜底由任务台设置打开本应用「SP 扩展安装包」普通卡片；卡片校验后调用 Hana 保存接口，需用户批准 `app/resources.write`。不从 settings 表面调用 saveFile，不改 sandbox 或退回 Blob 下载绕过限制。
- 文件保存的 `saved`、`canceled`、`conflict`、`download-started` 分别说明。发起浏览器下载不等于文件落盘；超时、断开、写后冲突或未确认回执先检查目标文件，不自动重试。

## 3. Hana 托管运行条件

基础 REST 与可选插件桥接分开处理。桥接需要实际批准 `app/runtime.execute`、`app/runtime.native`、`app/runtime.network`；说明其原生执行和网络范围，不扩大授权到无关应用。
保存安装包需要的资源写入权限不能替代这三项运行权限；三项运行权限也不能替代 Windows native identity 初始化。

Windows 才执行以下检查；其他系统按当前 Hana 官方文档和实际状态处理，不套用 Windows helper。

1. 阅读当前安装 Hana 随附的 APPS.md/native 指南，定位由同一 Hana 安装包分发的 `hana-win-sandbox.exe`，确认版本与来源；不使用任务台自带或网上临时下载的替代 helper。
2. 从可信宿主信息确认当前桌面 owner 与正在使用的 canonical `HANA_HOME`。不可假定为当前 shell 的用户目录、固定用户名或默认 `.hanako` 路径；不能通过转储环境变量/配置把凭据带进对话。
3. 若工具和权限允许，按随附指南以正确身份执行只读 `--native-identity-status --native-identity-home <已核实的 HANA_HOME>`。状态已就绪则跳过初始化；缺 helper、版本不兼容或状态不明先解决来源/状态问题。
4. 确认确需初始化后，先说明将改变 Windows 运行身份/权限、目标 owner 与 Hana 数据目录，并取得用户对此步骤的明确确认。仅当宿主当前提供受支持的提权机制时，使用同一官方 helper 的 `--initialize-native-identity --native-identity-home <已核实的 HANA_HOME>`。提权后仍须针对原桌面 owner 与同一 canonical home；身份变成另一管理员或无法确认时停止。
5. 无提权能力时，不尝试绕过 UAC、改 ACL、关闭沙箱、借 WSL/Docker 或伪造管理员权限。给最小下一步：让用户按其 Hana 随附指南完成官方管理员初始化；若该版本确有设置入口再给出实测入口，否则提供核实路径与参数供管理员审阅，不声称有不存在的一键按钮。
6. 初始化后重新只读检查；失败就报告这一阻塞。不要为了启动桥接杀 Hana/SP 主进程、抢占 3877 端口，或让用户把整个数据目录公开共享。基础 REST 可单独验收，不把它一起说成不可用。

只有用户允许启用桥接后，才使用现有任务台设置中的启用流程。状态查询不负责初始化或启动服务；不要自己运行 bridge.mjs 或改 runtime 参数替代宿主管理。

## 4. 在 SP 安装插件并安全配对

- 先检查 SP 已装插件和版本，兼容且已连接则跳过。安装/更新仅走 SP 公开支持的「设置 → 插件」选择已校验 ZIP 并启用；不写插件安装目录、数据库、ASAR 或私有状态。
- 有实际授权的受控 UI 工具且能核实当前窗口时，助手可以代做非敏感安装点击；没有时只请用户完成这一项：「在 SP 插件设置选择已校验 ZIP 并启用 Hana 任务台桥接」，等待完成再查，不承诺无人值守。
- 任务台的「启用并显示配对码」属于用户设置动作，不是 `sp_tasks_bridge` 的写入 action。不要虚构 pair 工具，也不要把 `/bridge/pair` 返回值作为普通工具结果读取。
- 配对码、REST 访问令牌、Hana 主令牌不得进入对话、模型可见工具结果、日志、命令行参数或截图/OCR。REST 优先使用任务台现有自动令牌读取；失败时让用户在敏感设置框操作，不向聊天索取。
- 只有当前工具明确支持不向模型暴露值的 secret-safe 跨应用通道，且用户授权这一具体传递时，才可代传配对码。普通剪贴板读取、浏览器抓取、shell 环境变量或「先读取后隐藏」不算 secret-safe。当前没有已核实通道时，让用户自行从任务台设置复制并仅粘贴到 SP 配对窗口；助手不要观察凭据区域。
- 不重置已有令牌、不把 Hana 主令牌交给 SP、不自动重新配对。用户说已粘贴或插件已启用，只是待验收，不是连接证据。

## 5. 只读验收与停止条件

完成操作后重新获取状态，不能引用操作前快照：

- `sp_tasks_bridge({})` 应返回 `enabled:true`、`running:true`、`connected:true`，没有 error/stopping，若有 accepting 则不能为 false；协议与当前任务台兼容。
- `sp_tasks_capabilities({})` 应确认已连接插件版本满足用户所需功能的最低版本及当前兼容性要求。旧功能可用而新功能 needs_upgrade 时，明确部分可用。
- 再做一次只读 REST 检查：任务台设置诊断成功，或已发现的 `sp_tasks_timer` status 成功。仅汇报连通性，不输出当前任务正文。必要时用已发现的插件 list 工具确认命令通路，不新增测试对象。
- 下载、安装回执、插件 enabled、接口 available 或 native 状态正常，都不能替代上述 fresh 运行/连接/版本与 REST 证据。无工具验证就明确「等待用户确认」或「未验收」，不能说已全自动接管。
- 不创建真实测试任务，不启停计时、不改日程来证明安装。任何写入 `outcomeUnknown`、安装结果不明或断开后先只读查询，不自动重放。
- 遇到缺权限、缺可信发行包、无受控 UI/secret-safe 通道或管理员初始化依赖，只停止对应步骤，保留已完成部分和原数据。最后用简短摘要列「已确认」「仍需用户一步操作」「尚未核实」，下一步必须可执行而非笼统让用户重装。

## 技能生效边界

本文件随应用位于 `skills/sp-tasks-setup/SKILL.md`，由 Hana 在应用装载成功后发现，不需要虚构 `contributes.skills` 字段。
应用及此技能必须对当前 Agent 启用；通常在新会话或宿主支持的技能刷新后可见，不承诺更新会改写已经运行的回合。
技能只提供指引，不改变工具目录、应用权限、系统身份或宿主安全规则。
